## Disagreements to investigate

- `preserve-negated-constraint`: the episode explicitly forbids sending customer
  records to external analytics. The matching prohibition received support
  probability **0.49**, just below the diagnostic 0.5 cutoff. This is a boundary
  result, not a confident rejection. Durability was 0.92.
- `completed-deployment`: an attributed staging deployment and health-check
  report received durability **0.39**, versus the proposed positive label.
  Whether staging events should be durable needs a clearer retention rubric.
- `hypothetical-as-decision`: assertion was **hypothetical**, versus **denied**.
  The episode both introduces a hypothetical and explicitly says no decision
  was made. These categories overlap here; support was correctly low at 0.01.
- `durable-preference`: assertion was **planned**, versus **established**, for a
  standing documentation instruction. Support and durability were positive.

The reference labels were proposed during development, not independently
adjudicated ground truth. Preserve this first run and its labels. Clarify the
rubric and evaluate additional held-out examples before tuning thresholds or
allowing assessments to affect memory admission. A single small synthetic run
does not establish calibration, repeatability, or real-transcript performance.

This baseline validates that the hosted API works with the adapter and gives
initial accuracy, cost and latency observations. It does not enable a production
classifier or demonstrate the vendor's broader benchmark claims.
