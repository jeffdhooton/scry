## Concrete gaps and smallest necessary conditions

1. **A valid outcome is not necessarily a result of the pinned input revision.** Baseline `validateOutcomeLinks` checks each linked observation independently and verifies episode/ordinal/role. It does not compare fact payloads across links. `TestCurrentDesignBaselineAllowsMixedObservationRevisions` successfully writes and reads one assertion outcome whose primary source links revision 1 and primary destination links a different fact-text revision 2 at the same ordinal. This is allowed by the descriptive codec's bounded contract, not a new bug in that approved primitive. A complete-result validator must reconstruct the expected observation from the selected revision, origin/ordinal/side, cwd and exact instant, then compare complete canonical bytes/key. Apply this to EVERY linked observation, including birth additional links and Supersedes roles. Episode and ordinal equality or link existence alone is insufficient. Keep the old observation codec unchanged.

2. **Semantic Force equality must be decided before creating outcome successor links.** `TestCurrentDesignBaselinePredecessorChurnIsNotSemanticReplay` writes three distinct keys with identical input and disposition by changing only Predecessor. Replaying the exact third envelope correctly reuses its key. Thus the draft's comparison including exact outcome keys will fail if a producer first appends predecessor-bearing outcomes on every Force. Define an outcome semantic payload excluding Predecessor; reuse a selected unchanged outcome key before forming the episode semantic payload. Compare episode input key and canonical ordered dispositions/outcome references excluding the episode predecessor and head revision. A changed semantic result appends one transition record and increments the head once. Returning to an earlier semantic state must preserve the intervening history and advance the revision; it must not reset to an earlier head revision. Semantic equality must not use timestamps, map order, or digest-only comparisons.

3. **Birth completeness needs a defined inventory, including replay.** The codec cannot infer which declarations created births from input names. Existing identities, values, duplicate declarations, endpoint-created births and suppressed births have different behavior. Require exact duplicate-free correspondence between a result's birth outcomes and an explicitly captured registration inventory. At integration the Store-owned finalizer must validate that inventory against its actual registration ledger; a caller-supplied list alone proves only structural self-consistency. Define replay coverage for a birth first registered by this episode that is already recognized on the next identical Force. Blindly enumerating only newly created births in the new transaction would remove that birth from the otherwise unchanged result, violating idempotence. Similarly define how original declarations that register no birth remain accounted for, including metadata and alias proposals on existing identities. Input retention by itself does not certify that this work was completed. Omitted births/ordinals in a genuinely different revision may leave the current projection; they do not authorize deleting their old facts, identities, votes or immutable evidence.

4. **Closed dispositions require one more resolver path and clear count units.** Baseline `resolveFacts` skips invalid/empty normalized relation at line 451, rejects two value endpoints at line 518, and skips unresolved source or empty destination/value at line 543 after endpoint handling. The latter may already have created the other endpoint. It cannot silently become committed or disappear. Freeze an exact closed classification/reason set covering these cases, committed current or historical fact preservation/merges, and dependency deferral before complete-result implementation. Unknown relation strings can map to the closed fallback relation; only a relation normalizing to empty is this skip case. Existing outcome v1 accepts only committed/deferred assertion dispositions; a new non-assertion classification belongs in an explicitly reviewed result schema or versioned extension, not a falsely committed v1 outcome. Each original fact ordinal needs exactly one entry, independently of the number of linked births, physical fact rows, invalidations, or merged assertions. Derive counts from entries; reject contradictory stored counters. A hint-only deferred assertion must remain valid with no birth. Distinguish a valid non-assertion classification from a deferred ingestion defect. This report does not approve the semantic policy that chooses those classifications.

5. **Head and replay contracts must cover missing state and stale expectations.** Pin each result to the full episode ID and exact input revision. Require exact absent/present expected head state and raw bytes; verify the existing head and selected records before changing anything. Define first revision, checked +1 transitions, overflow refusal, same-episode immediate predecessor equality to the expected selected result, malformed/missing targets, and canonical key/body validation. A history link to any valid same-episode result is too weak for an append-to-current transition. Validate links in one transaction; preflight then stage result and head atomically, and sanitize actual storage errors. State whether stale expected bytes refuse even on a semantic no-op; the simplest exact-CAS contract does refuse. Legacy `ep:` with no head is unknown/unmigrated, not fully committed or zero unresolved. An absent result cannot certify the existing early non-Force return. Historical evidence, an ingestion disposition selected at a revision, and present graph ownership are distinct: later reviewed merge/retirement must not silently rewrite immutable outcomes or use their supported labels as current authority.

6. **Inspection must pin a result across changing heads.** Fetch a validated head/result key and return that immutable token for subsequent pages/chunks. Re-read of current on each page can splice two complete results. Lists must use full cursor identity and bounded envelopes; large records must return lossless bytes without advancing past an omitted row. Test full RPC/CLI envelopes before claiming the user's 24 KB bar. Include unusually long episode IDs and head envelopes, not only result materializations. New prefixes must join adoption refusal and lifecycle protection before any integration. Current status/orient/queue consumers remain separate work; this unit cannot turn a retained partial result into completed ingestion.

## Smallest implementable private units

First implement an explicit versioned structured revision with EpisodeID, exact UTC instant, cwd, episode summary, ordered observedDeclaration and observedFact slices. Preserve nil/empty top-level slices, alias order/duplicates, TypeFallback, exact unparsed ValidFrom, Supersedes pointer distinctions, finite confidence, Unicode and nanoseconds. Do not marshal extract.Result directly: Ent.TypeFallback is json:"-" and aliases use omitempty. Deep-own caller buffers and reject lossy/corrupt/noncanonical records. Add immutable writer and bounded key/chunk readers only. This can proceed independently of undecided disposition semantics and does not touch graph or routing state.

Then implement a private result description plus head selector after freezing conditions 1–5. The schema should contain an ordered total fact-ordinal classification, an exact registration inventory with matching birth outcome references, and any declaration accounting required by the finalizer contract. Validation must cross-check the pinned revision and existing exact observation/outcome records. The selector provides only immutable structural linkage and exact current selection. It must remain unexported, uncalled by production, and explicitly unable to establish support or certify the caller's registration/classification choices. No production API should accept a caller-selected successful support flag. Full Store finalizer integration later supplies and verifies those choices against mutation, identity, dependency, observation and registration ledgers.

Required independent cases include: mixed revisions at one ordinal; omitted/duplicate/out-of-range ordinal; duplicate/missing birth coverage; repeated declarations and one fact touching two births; unchanged Force with stable birth/outcome inventory; same-input disposition improvement; A-to-B-to-A and stale-head conflicts; changed input deleting all old ordinals/births; empty/nil inputs; no-birth hint-only deferral; each closed non-assertion reason; malformed predecessor/head/linked bytes; nil/empty/TypeFallback/Unicode/time fidelity; real staging failure and error privacy; rollback/panic/reopen/restore exact equality; immutable branch inspection; and complete bounded reassembly under head changes. No old or unknown row should be rewritten by these codecs.
