## Mandatory decisions before implementation

1. **Canonicalize new selector-owned link/reference sequences.** Baseline `outcomeLineage` serializes Links in supplied order. The new characterization proves that reversing an otherwise identical link set creates two valid, different lineages and two durable outcome keys. Exact-byte retry remains valid in the old codec; the missing guarantee is deterministic enumeration before producing those bytes. Merely sorting top-level declarations/assertions/births does not close this case.

   The lead's reviewed correction is sufficient: normalize owned proposed outcome Links by decoded original occurrence: declaration before endpoint, then ordinal, original side src before dst, then closed role order declaration, primary-src, primary-dst, supersedes-src, supersedes-dst. Reject duplicate Key/Role pairs; preserve every annotation and materialization value. All links must first match the pinned input, making this ordering unique within one accepted revision. Require persisted outcomes selected by the new selector to already have that order; never rewrite/adopt arbitrary older V1 outcomes. Sort each declaration's birth references by the canonical Births first-observation order, after verifying all references exist and are duplicate-free. This changes only the new selector's admissible representation, not the existing V1 outcome contract. Encode/decode normalized owned values before lineage and semantic comparisons, including the existing UTC birth normalization.

2. **State exactly what head reads prove.** Head has the only uint64 revision; results have predecessor keys but no transition revision. A bounded read of the selected result and immediate predecessor cannot prove that Revision equals the full historical transition count. For example, replacing a valid noninitial head's revision with another positive value greater than one can still satisfy canonical key/body and immediate-link checks. This is a limitation deduced from the proposed record shape, not a reproduced failure in unimplemented code.

   The lead explicitly selected this finite contract: positive revision; Revision 1 iff selected result predecessor is empty; Revision >1 requires a valid, distinct, same-episode immediate predecessor. Writer checks exact expected existence and raw head bytes and advances by checked +1 only on a semantic change. Reader claims LOCAL structure only, never exact historical count, immunity to raw tampering, or integrity of an arbitrarily deep chain. Even Revision 2 attached to a predecessor with its own predecessor is outside the stated full-count proof. A stronger promise needs additional per-result revision data or a complete history walk. Do not silently add either to this unit. Validate the immediate predecessor's complete own input/dispositions/observations/outcomes, but do not recursively walk its episode predecessor chain under a purported constant-depth contract. Its different input revision is validated against ITS own InputKey, not the selected input.

3. **Keep staged output separate from commit reporting.** The private writer may return owned staged result/head data and derived descriptive counts; it must not return a successful Applied/Committed flag or imply durable success. The existing admission harness has an injected finalizer and returns only error; the future fixed outer wrapper does not yet exist. A writer in finalizing phase cannot observe its eventual outer Commit failure or sanitize that later error. Preserve the requirement that the eventual fixed wrapper sanitizes actual commit errors and returns no usable committed report on failure. Do not claim this unit has implemented that wrapper, production commit reporting, or an unforgeable support certificate. No new callback/finalizer injection is needed or approved. The new synthetic real-conflict test below demonstrates why this boundary matters.

4. **Permit derived immutable deduplication without permitting historical selection.** The draft says an absent/different current outcome lineage starts with empty predecessor, but also says historical outcome keys may be reused only when they are currently selected same-lineage unchanged outcomes. These are incompatible in A-to-B-to-A when B omits A's lineage: recreating A with empty predecessor and identical complete bytes necessarily derives the original historical A outcome key. Its occupied-row full-byte equality is exactly the existing immutable writer's contract. This contradiction follows directly from the specified content-addressed shape and old codec source; it does not require an unimplemented-selector test. Correct the prohibition to forbid searching/selecting arbitrary history as predecessor, support, or current authority, while explicitly allowing complete-byte-equal immutable deduplication at the internally derived key. The episode result must still link B and advance the head revision. Alternatively refusing this transition would break the intended replay contract; adding a nonce to force new outcome keys would change the old codec and is not recommended.

These are concrete implementation constraints within the authorized private unit, not a request for production permission. The lead's ordering and counter corrections are accepted as an addendum. Item 4 is an additional necessary correction identified during this review, explicitly accepted by the lead in subsequent correspondence, and must be recorded before implementing. The staged/report distinction is already required by the frozen design; the implementation and review must preserve it literally.

## Structural coverage and remaining claims

**Declaration and fact completeness.** Exactly one ordered declaration entry per pinned declaration and one ordered assertion entry per pinned original fact is executable. Require Ordinal equal to slice index and exact observation origin/side/ordinal, in addition to full byte matching. Matching *some* observation from the revision is insufficient for a specific slot. Nonnil classification arrays preserve a canonical zero-entry representation while InputKey distinguishes nil versus empty source arrays. Every declaration survives, including repeats and conflicting metadata. Both original primary observations survive every assertion classification, including empty endpoints and skipped relations. Declaration kind is descriptive; identity-mention cannot certify accepted metadata, aliases, or policy completion.

**Birth coverage.** Require exact duplicate-free Birth tuples, first observation keys and slugs, with canonical first-observation traversal order. Verify first observation provenance, birth occurrence/origin/name/time, and exact primary/declaration role; endpoint side comes from the explicit first observation because the Birth tuple itself has no side. A natural slug is not a birth inventory. A declaration reference must resolve to one listed birth whose outcome includes that declaration observation, and each birth outcome declaration link must have the reverse reference in that exact declaration entry. Value/deferred declaration references remain empty under the chosen schema. Reject unreferenced extra proposed outcomes and missing/duplicate local outcome addresses, not just malformed outcomes that happen to be used. Each committed/deferred assertion has exactly one local assertion outcome and each birth exactly one local birth outcome. These cardinality checks make the stated "one outcome per referenced" condition executable.

The selector cannot discover an omitted creation merely because its proposed inventory is internally consistent. That limitation is explicitly admitted and appropriate for this unit. Registration completeness later requires the finalizer's actual creation ledger plus selected prior-result evidence. Retained no-assertion birth rows describe prior occurrences and do not select live generations. Different extraction may remove old births from the current result, preserving their history and all old graph content. No birth-registration implementation PASS is supplied by this review.

**Replay inventory.** For identical input, a formerly supported birth becoming an established entity must retain the same original birth/outcome inventory after the finalizer checks current lifecycle state; fresh-registration-only enumeration would falsely remove it. This is an explicit future-producer duty. Synthetic selector tests must supply the same inventory on replay and also exhibit the incorrect fresh-only alternative; they cannot be labeled real Force integration tests. No-assertion carry-forward is descriptive and grants no slug-reuse authority. A changed InputKey may retain an old first observation only when all retained links actually match the new revision; summary-only revision changes can legitimately preserve occurrence links while changing InputKey.

**All-link full pinned revision.** The existing input matcher supplies full observation key/raw matching and is suitable as a building block. Apply it to every declaration reference, both primary assertion references, and every outcome link, including extra birth links and each supersedes role. Validate exact full persisted InputKey/raw and episode provenance; no digest-only or episode/ordinal-only shortcut. For committed/deferred assertion outcomes, require the matching assertion ordinal and primary roles. If Supersedes is nonnil, both supersedes roles must occur through exact matching original primary observation keys; neither role means speculative birth or graph endpoint ownership. Old baseline V1 outcomes with mixed revisions remain valid under their old descriptive contract and must be rejected only by the new selector.

**Counts and skips.** Baseline `resolveFacts` normalizes relation and skips empty normalized relation before endpoint stubs; two value endpoints increment FactsRejected and skip; it also skips empty resolved source or empty destination/value after endpoint handling, which can already have created the opposite stub. The proposed non-assertion versus unresolved distinction accounts for these paths without treating missing outcomes as committed. Unknown relation may map to fallback and is not the empty-relation reason. Missing-source/missing-destination refer to the proposed resolver disposition, not necessarily an empty original string: inverse relations and value-source reversal can change final sides. The eventual policy must settle reason selection where multiple failures apply, including source/destination precedence after transformation; that semantic choice is explicitly outside this descriptive codec. No extra classification is needed for the private record shape.

Derive committed/deferred/non-assertion/unresolved counts by original assertion ordinal, not outcome rows, physical current/historical fact rows, invalidations, linked hints or births. Their sum equals original fact count. Declaration-deferred is separate. Birth-supported and birth-no-assertion sum to inventory size and count selected descriptive birth outcomes, not current live supported identities. A hint-only dependency may be deferred with no birth. Existing ep without head is unselected, not a zero-unresolved certificate. No selected result means no result-derived counts claimed as known. This unit does not fix Apply's old non-Force zero Stats early return or queue/status/orient completion semantics.

**Semantic reuse and ABA.** Clear incoming predecessors and require them originally empty; normalize owned proposed outcomes, then compare canonical same-lineage outcome values with predecessor cleared against at most one CURRENT selected outcome. Same value reuses its exact key. Changed same lineage appends with current same-lineage predecessor; absent/different lineage starts empty. Build episode equality only after that decision, with its own predecessor cleared and exact ordered resolved outcome references. Check full expected head before equality, so stale identical requests refuse. Semantic no-op performs zero writes after validating current and all linked state. Genuine changes link the exact expected selected result and increment once. A-to-B-to-A creates a new transition rather than resetting the head or searching arbitrary historical outcomes. A missing current lineage after B permits a new predecessor-empty A outcome; an already occupied immutable byte-identical outcome row may naturally yield its existing content key through immutable deduplication. That is exact addressing, not historical selection authority. Tests must not incorrectly insist every return to old content creates a novel outcome key; it is the episode transition/head that must advance.

**Transactions and ownership.** Before idempotence require a genuine live finalizing admission facade, valid active transaction, and no prior poison. Ordinary root/body/closed misuse must refuse; caught writer failures poison the enclosing owner. Deep-own all caller slices, pointers, materialization buffers, expected head bytes and returned buffers. Preflight all proposals and old state before staging. Stage changed outcomes, result and head in the same outer transaction; fully compare occupied immutable bytes. Badger staging failure, callback failure and panic roll back everything; real commit failure leaves no newly selected result. Sanitize writer errors to the local static sentinel and allowlisted TxnTooBig/Conflict classifications, never raw value-bearing storage messages. Future outer commit errors need the same boundary. Postcommit observer panic remains the coordinator's existing committed-state semantics, not a promise of rollback.

**Bounded inspection and metadata.** A token with hashed head key, full raw-head digest, revision and fixed-size result key can be bounded for long EpisodeID. It is an inspection token, not a substitute for the writer's full raw expected-head CAS. Retrieve and validate full EpisodeID from the selected input/result/head within one view; digests do not replace full identity equality. Chunk reads pin the immutable result key across all pages even if current head changes. Enforce complete internal JSON/base64 chunk-envelope budget, offsets, forward progress, EOF and owned bytes, including long IDs, Unicode escapes and large embedded materializations. No public 24 KB RPC promise is proved by this private budget. Add exact io-episode:/io-head: prefixes to reserved-family refusal, including malformed and present-empty rows; this does not authorize adoption or demonstrate protection against all existing lifecycle-unaware writers.
