## Disproof findings

**Complete slots and outcome association.** `validateEpisodeDescription` requires declaration and assertion counts to equal the pinned input, ordinals to equal actual slice positions, and keys to identify the exact declaration or primary endpoint slot. It rejects unknown declaration kinds and assertion kinds/reasons. Its used-key accounting and writer association require exactly one outcome per birth and committed/deferred assertion; other assertions cannot carry an outcome. Independent 38-case coverage challenged existing-valid keys in wrong slots, swapped arrays, nil lists, missing/duplicate/extra outcomes, two differing outcomes at one local address, a separately valid extra birth outcome, caller durable keys/predecessors, and absence/presence expectation mismatches. Each failed with zero returned selection and a static safe sentinel; swallowing each failure still rolled back. The final tests inspect the active transaction before returning, proving preflight refusals did not stage partial rows.

**Birth inventory and observations.** Every first observation matches full canonical pinned input bytes and real episode provenance. Birth tuple episode/ordinal/origin/name/instant must match that exact observation and the full outcome birth tuple, with a matching original declaration/primary role. Slug and first-key uniqueness also preclude duplicate identical full birth tuples. Birth order is strictly declaration-before-endpoint, ordinal, src-before-dst. Declaration references are checked in both directions and cannot attach to value/deferred declarations. Independent mutations covered birth time by one nanosecond, name, origin, occurrence, first endpoint side, duplicate slug/first key, missing birth, omitted/additional/duplicate references and reordering. The multibirth fixture includes repeated declarations, a declaration referencing two births, and a birth originating at an endpoint.

`episodeBasis.outcome` validates every linked persisted observation, including unused-to-find-the-birth links and each supersedes role. Independent tests added an extra otherwise-valid birth or hint link from different fact bytes at the same ordinal; both refused. The positive fixture places both supersedes roles on the same original primary observation, which the frozen contract allows. Supplied tests additionally demonstrate no-birth hint deferral and refusal when either role is missing. Non-assertion/unresolved entries retain both exact primary observations while having no V1 committed/deferred outcome.

**Canonical equality and transitions.** Canonicalization owns proposed result and outcome values before sorting. It preserves materialization and annotation bytes, normalizes birth instants to UTC, sorts links by exact occurrence then role, and sorts declaration birth references by canonical birth inventory order. It does not silently reorder declaration/assertion/birth arrays. Twenty-five deterministic random outcome/link/reference permutations and equivalent second-offset timezone representations yielded identical selected results, exact head bytes and unchanged durable rows. Supplied tests prove persisted noncanonical selected link order is refused; the old codec and old counterexample tests are unchanged.

Source review confirms predecessor-free semantic comparison uses only the current selected exact lineage. Unchanged same-lineage outcomes reuse their current keys; changed ones link that current key; absent lineage begins without a predecessor. The full episode equality check occurs after resolving outcome keys and after checking exact expected head existence/raw bytes. Supplied tests exercise same-input disposition improvement, stable retained birth inventory, A-to-B-to-A with B omitting all old occurrences and exact historical outcome-content deduplication, and stale identical-head refusal. The new episode transition still links B and increments once; immutable history remains byte-identical. The new independently authored local-history case also exercises A/B/A with unchanged outcome content and changed descriptive reason.

**Closed counts and admitted limits.** Fact counts derive from each input assertion once; declaration-deferred and birth counts are separate. Supplied tests exercise all four non-assertion/unresolved reasons, no-birth hint deferral, empty/nil input revision distinction and legacy episode-without-head as unselected. Independent fixtures count two deferred assertions and three no-assertion births. The final additional test exercises three supported birth descriptions with exact generation IDs/materializations while confirming no live entity exists; the selector creates none. Then a fresh-only inventory omits them, yielding a new current result while preserving the historical description. This accepted behavior is an explicit limitation, not support proof: the future fixed finalizer must validate actual registration completeness, retained prior inventory, accepted metadata, semantic dispositions and live lifecycle state.

**Selected and immediate historical validation.** The reader checks canonical head/result key and bytes, complete own input/observations/outcomes, positive revision, and revision 1 iff result predecessor is empty. A noninitial selected result also requires a valid distinct same-episode immediate predecessor, validated against that predecessor's own input. Supplied tests change the input revision and then corrupt only the predecessor's input, causing both read and semantic retry to refuse. Independent corruption tests cover present-empty, duplicate-field, unknown-field and wrong-episode content in selected head/result/input/observation/outcome rows; episode provenance cases cover empty/wrong identity and duplicate case-insensitive identity fields. Every read/retry refuses without repairing bytes. Unrelated unknown episode metadata is outside the inherited provenance codec's identity/time checks and was not falsely tested as forbidden.

The bounded reader intentionally does not validate full history length. My raw synthetic fixture corrupts the result two predecessor links away while leaving current/immediate records valid, sets the head to MaxUint64, and still reads successfully. An unchanged exact-CAS replay is allowed at MaxUint64; a genuine change refuses without writing. Corrupting the immediate predecessor then refuses. This matches the frozen LOCAL counter contract and must never be reported as global chain integrity.

**Transactions and ownership.** Phase, genuine active transaction and prior poison are checked before any no-op. Supplied tests cover root, ordinary facade, admission body, closed facade and prior poison. Independent tests successfully stage a change, catch a later invalid writer call, then try the exact cached proposal; prior poison blocks the no-op and the outer transaction rolls back everything. Independent actual value-size refusal and transaction-capacity exhaustion both return zero selection, retain the static local sentinel (plus ErrTxnTooBig where applicable), hide a synthetic secret canary and poison even when caught. Actual finalizer errors and panic roll back; a real concurrent Badger write of the same head bytes causes ErrConflict after a nonempty staged selection was captured. No staged result persists. The captured value is demonstrably not commit proof. This unit cannot sanitize its later outer commit error; that remains a future fixed-wrapper duty under the frozen contract. Existing postcommit observer semantics are unchanged; the selector itself emits no events.

Independent tests mutate caller birth pointers, assertion ordinal pointers, materialization bytes, links, declaration references and returned head/result buffers after changed staging, then read the still-open transaction and the committed store. Both remain exactly equal to a separately serialized expected result. A separate no-op ownership test also preserves all bytes. No data race or concurrent caller-buffer mutation is claimed safe.

**Internal bounded inspection.** Tokens contain hashed head identity, raw-head digest, revision and fixed-size immutable result key, never the full potentially long episode ID. The token is not the raw-head CAS. Independent long IDs contain Unicode, quotes, newlines and backslashes. Complete JSON/base64 envelopes fit budgets 512, 513, 1024 and 24576; all pinned chunks reassemble exact original result bytes after the current head changes. Every chunk has exact offset progression, with no skips; EOF, past-EOF, negative/maximum offsets, invalid budgets and wrong episode identity are checked. Supplied tests also verify reopen byte equality. These are internal result-record chunks, not a public RPC/CLI 24 KB guarantee or a combined envelope containing all linked materializations.

**Reserved families and production boundary.** Both exact new prefixes refuse legacy adoption preview and apply for malformed names, present-empty values constructed from nil and empty buffers, and malformed nonempty values. This is only reserved-family refusal. It does not enable adoption or prove all lifecycle-unaware writers safe. No production selector caller, callback escape route, graph mutation or identity/alias policy integration was introduced.
