# Delayed birth — independent bounded architectural disproof

2026-09-06. Reviewed proposal SHA-256 `a701291a87c2556f378fa74cb21dbda6732e3ff9e2ded3d7b9b2dcf2709043c0`, baseline `4592a41f430c884aa6e24abcf6638925d0c2a37e`.

Conditional GO for a private, uncalled, read-only ordered identity-resolution overlay experiment after freezing the corrections below. I found no actual resolver behavior that requires unsupported identities to have real en:/al: writes. Their temporary visibility can be represented in memory. This can eliminate ordinary unsupported-birth raw undo, but only by implementing a substantially complete resolution and fact-planning boundary. NO-GO for treating this draft as an approved replacement controller, production integration, accepted-support policy, or completed architecture. The plan's final raw-reference argument is a useful narrow invariant, not proof of assertion preservation or ownership.

The main distinction is between provisional visibility and durable authority. Candidates that eventually remain unsupported must nevertheless stay visible through the entire ordered resolution pass. Positive and negative dependencies on that visibility must be recorded. A baseline-only lookup or a greedy support filter changes useful facts. Eliminating writes does not eliminate the alias decision problem; the complete final relationship policy remains mandatory.

## Concrete counterexamples and the contracts they require

### 1. A rejected discovery affects later relation semantics

`TestDelayedBirthRejectedDiscoveryChangesLaterStatus` compares the same useful `Borealis status Nimbus Core` assertion with and without an earlier `!!! uses Nimbus Core` assertion. The earlier assertion cannot resolve its source and adds no fact. Existing resolveFacts nevertheless creates Nimbus Core's stub. The later assertion therefore becomes `Borealis related_to nimbus-core`, an entity edge. Without that discovery it becomes the exclusive attribute `Borealis status "Nimbus Core"` and no Nimbus Core entity exists.

This is direct execution of resolve.go's Rule 3, establishedMentionIdentity and status transformation, not a hypothetical alias concern. “Resolve only accepted assertions” or dropping provisional discoveries after each rejected assertion fails this case. An overlay must reproduce both-endpoint discovery, ordered visibility and the distinction between a known provisional identity and a value. In the first execution Nimbus Core eventually IS supported by the later accepted primary; it cannot be classified as unsupported at discovery time. Register/link its original destination observation before proposals, even though the discovered fact will be rejected. The useful later fact retains a separate original-to-final mapping and dependency on this discovery.

The lead clarified during review that ALL registered discoveries remain in memory through complete ordered resolution and selection occurs afterward. That defeats this counterexample. This clarification is not attributed to the frozen document's bytes.

### 2. Provisional aliases route later declarations; canonical conflicts are not optional alias rejections

`TestDelayedBirthProvisionalAliasRoutesAndConflicts` declares Cobalt(service) with the immediately admissible alias Cobalt daemon. A later Cobalt daemon(service) declaration resolves to Cobalt, and its useful fact is stored on Cobalt. A later Cobalt daemon(machine) declaration instead follows the cross-type resistance path toward its natural slug and then fails PutEntity's canonical index ownership preflight. Apply rolls back with ErrAliasClaimed and zero Stats, even though the first declaration has no primary fact of its own.

An overlay that simply returns a candidate for every declaration's natural slug changes the service case. One that drops unsupported Cobalt and quietly lets the machine claim its canonical spelling chooses a new winner. One that labels the machine's canonical failure an ordinary optional alias rejection risks storing an identity without its canonical claim. Freeze this policy: optional proposed aliases can remain rejected while independent primary assertions proceed; an unavailable canonical/name or necessary endpoint route defers its exact dependency component. Preserve unrelated components and show the blocked assertion as unresolved. Do not recompute the machine's owner after removing Cobalt from materialization.

A repeated alias-routed declaration must link to the first candidate handle, not call first registration with a new natural slug. A same-slug but unrelated canonical name still refuses. A real exact natural-name identity wins over a stolen alias route; canonical homonym scans and retained nonnatural survivor-name handling must include the appropriate overlay entities and full lifecycle checks. The episode-local resolvedEntities map takes precedence in establishedMentionIdentity; exact fallback and validated listed aliases follow. These are different lookup routes with explicit rules, not one generic map.

### 3. Proposed metadata must evolve in order while every input remains immutable

`TestDelayedBirthRepeatedDeclarationAndArtifactState` declares Nimbus Core as concept, then project, then machine, with conflicting descriptions. Baseline retains the first description, upgrades concept to project, drops the box alias on revalidation, and does not retype the project to machine. Repo references remain. A `queue.go` declaration typed value is retained as a concept artifact and used as a fact endpoint; `validation_failed` typed value gets no entity.

The overlay needs the evolving proposed Entity projection, alias removal proposals, creation tuple, and separately preserved full original declarations, including each type, TypeFallback, description, alias order/duplicates and repo context. It must not choose final metadata by last declaration, concatenate unvalidated aliases, or let the second mention select legacy attestation because a provisional identity is visible. DeclaredValues is computed over all declarations before resolution; affirmative same-episode names protect against conflicting value names/aliases independent of order. A blanket “discard all value declarations before discovery” is not equivalent. Artifact early returns, exact-established protection and contextual/durable value evidence each need distinct coverage, with typed lifecycle failures propagated through protected paths.

Original fact sides must be captured before Map's inverse swap and any subsequent value-source swap. Hints keep independent supersedes-src/dst annotations on their carrying original observation; they cannot register births. Transformations can put the original destination on the final source side or turn a final destination into an attribute. Candidate selection must use final typed primary entity endpoints, not original endpoint strings.

Existing metadata-only declarations are a separate utility requirement. Current resolveEntity updates an established identity without requiring a fact in this episode. The draft's phrase “supported existing identities receive ... metadata updates” must not become a new fact-support filter for old entities. Keep independently authorized existing metadata updates, with exact relationship/lifecycle validation and recorded conflicts; baseline entities are never unsupported cleanup targets.

### 4. The compact cache is not the same as the current transaction view

`TestDelayedBirthCompactCacheHasDifferentVisibility` seeds an existing Borealis claimant with one prior normalized alias vote, refreshes the name cache, then creates Cobalt Atlas. With the old cache, AdmitAlias admits Cobalt Atlas daemon to Borealis on its second vote. After RefreshCompactIndex, the identical request refuses because the spelling names Cobalt Atlas plus kind words. The current cache refreshes by elapsed time, not on every en write. Direct GetEntity/ResolveAlias and canonical scans already see the write.

Therefore “same semantics” is underspecified even before introducing an overlay: mirroring a transaction's newest entity map while using the old compact cache is inconsistent, and making the cache fully current changes some baseline decisions. Freeze an explicit deterministic overlay cache contract. My recommendation for the private next unit is versioned complete name/slug/token indices updated at each identity proposal transition, with ambiguity refused instead of selecting a new winner; retain this characterization as an intentional correction to stale-cache admission, separately reviewed before production. Do not silently claim byte-for-byte baseline equivalence for the stale case. Do not propagate provisional indices to global cache, and dispose all state on success, error and panic.

This existing-claimant example uses legitimate old legacy votes only as baseline characterization. It does not approve private B or permit old att: votes to authorize any new candidate. All attestation proposal entry points must be gated by the genuine handle before the first proposal, including rejected proposals and repeated mentions; one new-candidate vote per episode remains the proposed B rule.

### 5. Preflight must execute virtual Phase A before deciding Phase B eligibility

`TestDelayedBirthPhaseABackdateChangesHintEligibility` seeds an Atlas uses Borealis fact whose start is one day AFTER the episode time. On the untouched snapshot, a hint cannot invalidate it. The same episode also restates that triple with a start one day BEFORE the episode. Phase A relocates the row to the earlier address, raises confidence and unions provenance; Phase B now invalidates it at the episode time. This happens even when the hint-bearing primary appears before the restatement in input order.

A snapshot-derived “ineligible hint, no dependency” decision is wrong. Track the virtual exact old and relocated keys, all read/write dependencies, and the ordinal that supplied the change. Removing a deferred Phase-A assertion must not leave its hypothetical backdate influencing an accepted hint. This is more than deferring directly unresolved endpoints. Exclusive invalidation also reads ordered current state, including whether an existing fact begins before the episode and whether an incoming assertion must itself be historical. A complete dependency component must cover matching, confidence/provenance changes, relocation source/destination, historical occupied addresses, hints and exclusive targets before any real Phase A write.

The lead's clarification to simulate Phase A and Phase B in owned virtual FA state addresses the ordering point. It still requires executable dependency isolation and exact-address tests. Calling the existing mutating helpers during a “planning pass,” or executing then selectively undoing their facts, is not this design.

`TestDelayedBirthSameEpisodeHistoricalSupportAndFallback` additionally creates a backdated Borealis assertion, invalidates it through a later same-episode hint, then restates its exact now-historical address. The row stays closed while confidence rises. Two exact fallback repeats coalesce on the ordered Phase-B state. Four new identities all retain actual current/historical support. A single query of the initial database cannot plan these operations. Unknown relation fallback is not an empty-relation rejection.

### 6. Old raw ownership defects can change without changing alias bytes

`TestDelayedBirthStaleSelfClaimDoesNotProveIdentity` seeds al:atlas and an unlisted old spelling pointing to absent atlas, with zero facts. Normal Apply creates Atlas and a useful fact successfully. Both old alias rows are unchanged, but their target went from absent to a newly created identity, and the unlisted spelling is still not a valid routing mention.

The registry's zero-baseline-FA check and absence of en/selection keys are not sufficient authorization for that birth. The final relationship closure must include EVERY raw alias whose owner is a changed identity, even an untouched key no entity lists, and every listing of every affected normalized spelling. Compare exact owner/absence, canonical versus alias occurrences, spelling bytes, natural-slug routes and recognized selector/consumption identity. A stale self-owner row does not make a new generation the owner of its old spellings. A changed absent-to-present relationship cannot use the unchanged-defect exception. Refuse/defer the implicated component until an explicit reviewed disposition exists; do not auto-claim or fabricate an old owner.

For A-proposes-k, A-releases-k, B-proposes-k, ordinary AdmitAlias currently refuses every genuinely other-owned key even after sufficient votes. A virtual release is not permission to transfer a baseline old owner's key. B's final claim must independently pass against baseline ownership, natural identities and every retained listing. If baseline was unclaimed and B has independent valid admission, no raw A restoration is needed; if not, reject the alias or defer its necessary component. Removed A proposals remain in outcomes and dependency history. Existing wrong/missing owners can remain only under exact complete relationship equality, never “old entity” or “same al bytes” exemptions. The previous identity-mutation review's closure is retained in full.

## The final-support claim is feasible but deliberately narrow

For a genuinely baseline-absent candidate with zero current/historical raw references, the first accepted primary using its exact slug cannot merge into a baseline fact with that endpoint: such a fact would contradict baseline-zero. After its first actual assertion, the permitted ordinary operations preserve endpoints: invalidation keeps a historical row; confidence/provenance merge keeps a row; backdate relocation deletes and re-puts the same endpoint tuple atomically; an exact same-episode repeat retains a row. An occupied-address conflict is an error or preplanned visible deferral, not zero-support success. On these assumptions, I found no correct accepted primary plan that yields zero actual support for its selected candidate. A final zero-reference result must atomically refuse as planner/accounting failure. No unsupported raw-undo fallback is needed.

This reasoning requires acceptance to mean the fully validated, dependency-closed plan, after all address and semantic conflict decisions. Preliminary syntactically valid primaries are not accepted plans. It also requires every actual fact writer to be owned and authorized, exact final ledger verification, and no endpoint-rewriting/deletion maintenance interleaved in the scope. A deferral after candidate materialization cannot quietly reduce the accepted set. A matched historical row created earlier in the episode supports the candidate even when current references are zero. Hint-only identities never enter the materialized set.

`TestDelayedBirthCurrentTripleSupportDoesNotProveAssertionPreservation` explicitly preserves the current unresolved bug: a later distinct sentence on the same nonfallback current triple merges confidence/provenance while retaining only the first sentence. Raw references survive, Stats reports FactsMerged, and the second sentence is absent from graph facts. That does not invalidate the narrow reference lemma, but it prevents using it to certify the accepted semantic plan. The original assertion-identity/recovery problem remains mandatory, with exact content/time/confidence/provenance preservation and no timestamp nudge or dropped facts. The overlay does not solve it by retaining a count or renaming the outcome.

## Smallest coherent private next executable contract

Freeze a private ordered identity-resolution planning harness first, with no production caller and no durable mutation. It owns canonical parsed revision bytes, a genuine registration scope and complete baseline identity/lifecycle/value/fact-veto views. Its BODY/program is fixed by the harness; no caller-supplied chosen owners, virtual raw after-images, accepted flags or cleanup lists. It may return owned descriptive proposals and typed resolution/dependency records after a fixed internal freeze; it must not select support, materialize B, write en/al/att/FA/observations/EP, or certify semantic admission. If the implementation uses a private test seam, do not expose it as the eventual public API.

Its minimum producer and lookup coverage is:

- All declarations and both primary endpoint discoveries in original order, including rejected facts' individually valid discoveries, empty normalized relation handling, repeated/type-conflicting declarations and artifact/value/context paths. Register before any new candidate proposal; link later observations through validated routing decisions, never treat mechanical links as permission.
- Typed lookup results separating recognized baseline identity, provisional candidate with exact handle/proposal dependency, value, absent, deferred identity and error. Implement separate declared-map, natural exact, validated alias, natural-slug occupant, canonical-homonym and compact/kind-name rules. No deferred/error result may become an empty slug, concept, value or ordinary alias rejection.
- Ordered proposed metadata and normalized alias add/remove state; every optional alias decision records its reason, witnesses, exact baseline controls and position. Complete versioned scans/indices must include provisional state without granting it established lifecycle authority. Legacy/new-vote choice remains explicit and must not silently use unapproved B source as proof.
- Every original fact has one typed primary record or explicit unresolved/rejected reason, with preserved ordinal, text/date/confidence, SupRef and original-to-final sides. Hints can refer to provisional identities already discovered elsewhere but never create candidates. This first unit describes dependencies; it does not yet choose exact FA targets or mutate a hint.
- Fixed freeze audits all proposal producers, genuine owner/phase/handle boundaries, original observations and immutable owned reports, and proves zero raw writes/events. Test no-op read-only transaction preservation, malformed controls, swallowed errors, storage failures, panic/closed use and cache disposal. Full baseline/final identity inventories detect final drift but are not proof against untracked transient writes; production all-writer exclusions remain.

The private unit's grade is finite: reproduce safe baseline declaration/endpoint decisions and explicitly classify the frozen conflict/cache deviations; demonstrate the eight characterizations above, original inversion/value/artifact corpus, exact canonical precedence/homonyms, repeated conflicting metadata, all missing/stolen/unlisted owners, and mixed unrelated utility. No support selection or fact execution should be added merely to make this primitive look complete.

Only after that independent review should a second private planner simulate BOTH fact phases over exact owned FA state, build dependency closure and preflight content/address conflicts. Its test bar includes a deferred restatement whose virtual relocation would otherwise change another hint, hint-only dangling/history/consumed identities, ambiguous fallback SupRef matches, exclusive dangling targets, unrelated components, same-episode no-ops/history, and preservation of the known current-triple failure. A separate fixed executor then proves the plan against actual owned writes. Planning and execution proofs must remain separate from raw support counts.

Before either unit becomes production, freeze the utility choices: optional alias rejection can leave independent useful primaries accepted; canonical/required-route conflicts defer their entire dependent mutation component; no rerouting after support selection; no all-episode refusal merely because an unrelated component defers; counts deduplicate original assertion ordinals and never label deferred assertions ingested. A completely deferred episode and mixed partial episode need durable inspectable originals and explicit current result state. Identical/changed Force, consumed selectors, no-birth hint outcomes, EP provenance and immutable successor selection remain separate mandatory contracts. The selector under separate review is not certified here.

For never-staged candidates, use Materialization=nil. Preserve the full original proposals in linked observations. If inspection later needs a combined proposed metadata projection, give it a distinct named/versioned schema and never call it an actual materialization. The lead proposed this correction during review; it is safer and simpler than the frozen draft's suggested synthetic materialization snapshot. Actual materialization, when eventually present, is a separately evidenced event/state.

The original EmptySlugSkipped baseline expectation intentionally commits one unsupported endpoint stub. It still passes unchanged here. A future production contract change must explicitly preserve its input for inspection while committing no unsupported node; the Nimbus continuation proves why that candidate must remain visible until all later resolution is complete. This is not permission to weaken the original test silently.

## Verdict limits and pins

The lead's clarifications resolve the strongest greedy-filter and materialization-terminology ambiguities, but do not by themselves establish complete producer coverage, cache policy, alias authority, fact dependency isolation or useful partial outcomes. Freeze those corrections before private implementation. Architectural feasibility is conditional; replacement of ControllerV3 is still a separate decision. No implementation, all-writer lifecycle adoption, status-value quality, performance, live prevention, cleanup, recall, binary/deployment, sweeps or whole-goal clause is approved by this report.
